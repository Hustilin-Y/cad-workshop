# CAD-мастерская: правила работы

Проект для проектирования и доработки деталей под 3D-печать на Bambu Lab P2S.
Claude Code пишет модель кодом, собирает, проверяет и отдаёт файлы; печатает пользователь сам через Bambu Studio.

## Окружение

- Windows 11, нативно. Код не привязывать к ОС: пути только через `pathlib`.
- Всё через `uv`: `uv run cad.py ...`, `uv run pytest`. Глобально ничего не ставить.
- Сеть только для `uv add`. Скрипты в сеть не ходят, к принтеру не обращаются (это проверяет тест).
- Blender не используем. GUI (Bambu Studio и др.) не автоматизируем.

## Профиль принтера

- Все допуски, стенки, габариты стола берутся из `printer.toml` через `cadlib`, никаких чисел в коде модели.
- Сопло по умолчанию 0.4, профили 0.2/0.6/0.8 уже описаны. Если пользователь говорит, что ставит другое сопло, сменить `nozzle_mm` (или передать в сборку), не правя модели.
- Пластик по умолчанию PLA; есть PETG, ABS, ASA. Если деталь для тепла, улицы или нагрузки, предложить подходящий пластик и сказать почему.

## Выход

- Для своих деталей: STEP + STL + 3MF в `parts/<имя>/out/`.
- Превью: PNG (изометрия + 3 проекции), его всегда показывать пользователю.
- Живой 3D-просмотр: OCP CAD Viewer в браузере, VS Code не нужен. Пользователь запускает `uv run python -m ocp_viewer` (локальный сервер на localhost:3939), модель отправляется туда через `from ocp_vscode import show`. Это необязательное дополнение: если вьюер не запущен, сборка не должна падать.

## Как работать

- Всегда начинать с уточнения недостающих размеров. Не выдумывать посадочные размеры: если не знаешь диаметр или расстояние, спроси (лучше замер штангенциркулем).
- Параметры детали держать в начале `model.py` с комментариями в мм. Новая деталь: `uv run cad.py new part <имя>`.
- Отверстия под винты, гайки, термовставки — только через `cadlib.fasteners` (ISO-размеры + допуски профиля), не рисовать вручную. Размеры вставок и магнитов у разных производителей разные: перед использованием спросить замер.
- Проверять геометрию на печатность в `_validate(p)` модели (стенки ≥ `p.min_wall_mm`, отверстию хватает места) с понятной ошибкой.
- После каждой сборки показывать пользователю PNG-превью и отчёт проверок, прежде чем считать задачу выполненной.
- Правки по комментариям делать через параметры, а не переписыванием геометрии, где это возможно.
- В `README.md` детали вести короткую историю: что поменяли и почему (например «зазор 0.2 → 0.3, туго садилось»).
- Для ремикса: сначала `inspect` оригинала, потом план правок в 2–4 пунктах, потом правки.
- Новый ремикс: `uv run cad.py new remix <имя> <файл>`. Оригинал копируется в `source/` только для чтения, его SHA-256 пишется в SOURCE.md, inspect запускается сразу. Ссылку, автора и лицензию спросить у пользователя и вписать в SOURCE.md.
- STL/3MF правятся через `cadlib.mesh`: `subtract`, `add`, `cut`, `scale`, `repair`. Инструменты (отверстия, пазы) строятся в build123d. STEP правится как своя деталь через `import_step`, так точнее.
- Если изменение объёма можно посчитать заранее, задать `EXPECTED_VOLUME_DELTA`, и сборка сверит его с допуском ±1%.
- Не трогать `remix/*/source/`: оригинал только на чтение, все правки в новый файл.
- Ориентацию для печати предлагать, но окончательно выбирает пользователь в Bambu Studio.
- Напоминать, что STL надо открыть в Bambu Studio и убедиться, что нет предупреждений о повреждённой сетке.

## Git

- Публичный репозиторий на GitHub (аккаунт Hustilin-Y), как портфолио. `out/` и `remix/*/source/` всегда в `.gitignore`: чужие модели не публикуются, исключение — сгенерированные нами заглушки `remix/example-*/source/` (CC0).
- Перед коммитом проверять, что в индекс не попали чужие модели, личные данные и пути вне проекта.
- Коммитить и пушить только когда пользователь просит.
